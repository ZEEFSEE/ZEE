## 执行前门槛

- [ ] 使用独立测试项目/测试部署，不使用生产私聊正文或生产写入目标。
- [ ] 确认测试凭据由授权人员通过安全渠道生成；不复制到报告、截图、终端历史或 GitHub。
- [ ] 为每个请求生成 request_id；只保存状态码、错误类别和必要的脱敏证据。
- [ ] 明确每个用例的预期副作用；认证失败用例不得写 DB 或 GitHub。
- [ ] 先执行只读/无效请求，任何有效写入用例都需要单独批准及隔离资源。

## 判定规则

- 任意 AUTH 用例意外返回成功，立即标记 `blocked`，停止后续写入测试并升级审查。
- 认证拒绝用例若产生数据库、仓库或其他外部副作用，判为失败。
- 不能只凭 CORS/Origin 判断身份已认证；无 Origin 请求也必须经过服务端授权。
- 不把 HTTP 200 等同于持久化成功；需用独立只读证据核实结果。
- 未执行的用例必须保留 `not_run`，不得写成 pass。
- 测试完成后记录函数版本、测试环境、执行时间、请求 ID、预期/实际结果、证据链接及执行者。
