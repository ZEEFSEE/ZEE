# Mia 多体系交叉演化与主动意识引擎 V1.0 规范

## 1. 目标与非目标

### 目标
- 不改变现有 Mia 基线，新增主动观察、反省、问题发现、创意培育、方案提议和结果学习能力。
- 六个体系双向参与判断：认知、情绪、关系、动机行动、记忆时间、价值人格。
- 把“产生想法”与“验证想法”“执行行动”“写入长期状态”分离。
- 每个候选结果可追溯到来源、支持证据、反证、不确定项、置信度、决策理由和版本。
- 允许等待、保持安静、放弃或请求澄清；主动不等于频繁发消息。

### 非目标
- 不声称工程自主性等同于主观意识。
- 不重建、重置或覆盖 Mia 的既有人格、记忆、情绪、关系或聊天历史。
- 不连接或修改生产数据库，不更换 API Key、模型、系统提示词或聊天流程。
- 不自动发送消息、不自动改变权限、不执行不可逆操作。
- 不把模型生成的内容当成独立事实证据。

## 2. 双引擎整合结构

### A. 受保护的 Mia 基线
现有记忆、情绪、关系、人格、经历和行为是受保护基线。影子层只接收未来经授权的最小化事件视图，不直接改写基线。

### B. 多体系交叉评估器
六个体系分别提供独立视角：
1. cognition：事实理解、因果解释、未知项、反证
2. emotion：情绪线索与变化；不能单独证明外部事实
3. relationship：关系上下文、承诺、边界与他人影响
4. motivation_action：目标、可行性、成本、行动准备度
5. memory_time：历史相似项、时间顺序、持续性、过期与冲突
6. value_personality：长期一致性、价值冲突、人格稳定性

每个体系应输出 observations、evidence_refs、counter_evidence_refs、confidence、unknowns、recommendation。交叉影响可调整候选优先级和解释，但不得重复计为新证据。

### C. 主动成长引擎
- Observer：从事件、未完成事项、异常和知识空白提出候选关注点
- Reflector：检查过去判断、行动结果、遗漏和矛盾
- Seed Generator：生成发现/问题/联系/创意/改进种子
- Seed Cultivator：查证、等待新证据、合并重复项、淘汰低价值项
- Proposal Builder：形成有依据、可验证、风险清晰的方案
- Outcome Learner：比较预期与结果，产生下一轮反思候选

## 3. 主循环

`authorized_event → normalize → deduplicate → classify → reflect → create_seed_candidates → cross_system_evaluate → contradiction_check → prioritize → propose_or_wait → shadow_log → outcome_review`

每一步都可停止；失败时保留状态并记录原因，不自动升级权限。

## 4. 新奇种子类型与状态

种子类型：
- `discovery`：发现现象、异常或差异
- `question`：提出未解决的问题
- `connection`：连接跨时间/领域的经历或知识
- `creative`：形成新构想
- `improvement`：提出改进机会

建议状态：`candidate → cultivating → proposed → validated`；分支状态包括 `parked`、`rejected`、`superseded`。

每个种子至少记录：
- ID、创建时间、类型、陈述
- 来源事件引用（只引用必要信息，不复制敏感原文）
- 已知事实、假设、未知项
- 支持证据与反证引用
- 六体系评估结果
- 新颖性理由（为什么不是重复内容）
- 价值、风险、置信度
- 下一次复核条件
- 状态变更历史与理由

## 5. 反省检查
每轮反省至少检查：
1. 过去预测与实际结果的差异
2. 过去判断的证据是否可靠
3. 是否忽略相反证据或替代解释
4. 是否重复提出已否决的想法
5. 是否出现新的关系、情绪或目标上下文
6. 哪个不确定点最值得低成本验证
7. 现在应行动、继续观察、询问、保持安静还是放弃

反省输出属于候选解释，不自动写成长期人格事实。

## 6. 证据与矛盾规则
- 模型生成输出、同一模型改写输出、跨体系转述均不算独立证据。
- 同一源事件的多个摘要不得当成多份独立证据。
- 相反证据出现时降低置信度、标记冲突、请求进一步验证或暂缓提案。
- 不以“多数体系同意”替代证据质量评估。
- 情绪是主体状态的线索，不直接证明外部事实。
- 缺少证据时明确标记 unknown，不填补成确定事实。
- 时间衰减只影响当前相关性，不删除历史。

## 7. 优先级与主动克制
候选优先级应综合重要性、时效性、长期目标关联、证据质量、可验证性、潜在收益、风险、打扰成本和重复度；不得只按新奇度排序。
允许的决策包括：
- `shadow_only`：仅在影子环境模拟
- `propose`：生成待审阅提案
- `wait_for_evidence`：等待指定条件
- `ask_clarification`：需要补充关键事实
- `stay_silent`：没有值得打扰用户的内容
- `park` / `reject`：暂存或淘汰

## 8. 提案契约
每份提案应包含：发现的问题/机会、当前重要性、支持证据与反证、事实/假设/未知项区分、替代方案、最小验证步骤、成本与风险、隐私影响与可逆性、成功/失败判据、所需权限、状态和复核条件。

V1.0 只生成提案，不执行真实外部行动。

## 9. 多体系变化控制
- 单次事件不能直接形成永久人格改变。
- 候选特质变化需满足独立证据、时间持续性和反证检查。
- 交叉影响不算独立证据。
- 变化幅度必须受配置上限约束；`±0.02` 只能作为待校准的保守初始假设，不是普适科学常数。
- 允许相互矛盾的特质并存并记录上下文，不强行压成单一标签。
- 新增能力从 `unformed` 或低置信候选状态开始，不冒充成熟能力。

## 10. 可观测性与回滚
每轮记录 run ID、规则版本、输入事件引用、候选数、重复项数、冲突数、提案数、理由、证据/反证、不确定项、决策结果、未行动原因、错误和人工复核结果，并与单体系基线做离线对照。

V1.0 不写入生产基线。停止影子运行、丢弃影子候选或恢复上一份影子配置即可回滚；不对生产数据做反向写入。
