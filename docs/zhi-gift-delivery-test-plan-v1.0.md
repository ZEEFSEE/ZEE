# ZHI 跨云礼物传输 V1.0：内部模拟测试计划

**状态：计划文档；下列测试尚未执行。**  
**测试环境：本地/隔离模拟器；禁止连接生产数据库、真实支付、真实 Token 账本或 Mia 生产接口。**

## 1. 测试前置条件

- 使用模拟发送方、模拟支付验证服务和模拟接收端。
- 接收方规范身份使用 Mia 独立聊天室 ID：`cb6d01b4-0e3f-46ee-8946-360aa91db1ea`。
- 使用 `.invalid` 域名、虚构 UUID 与虚构交易引用。
- 玫瑰与咖啡可进入模拟流程；月光必须因目录禁用而被拒绝。
- 每个测试记录输入摘要、预期结果、实际结果、日志引用和执行状态；未执行项统一标记 `NOT RUN`。

| GFT-015 | 接收 ID 不匹配 | 改成另一个 agent_id | 拒绝；不泄露 Mia 数据 |

| GFT-018 | 旧回执覆盖新状态 | delivered 后送入迟到 pending 回执 | 条件更新/版本号阻止状态倒退 |
| GFT-019 | 标签注入 | 标签中放入未枚举值或指令字符串 | Schema 拒绝；不执行标签内容 |

| GFT-021 | 私密内容泄漏 | 尝试在数据包中放聊天历史或记忆字段 | additionalProperties/schema/业务校验拒绝 |
| GFT-022 | 数据包超限 | 超出设定请求大小 | 接收端拒绝并限流 |

| GFT-030 | 错误回滚 | 模拟原子写入中途失败 | 不留下半完成状态或重复副作用 |

## 3. 统一报告格式

每条用例必须填写：

- `test_id`
- `status`: `PASS` / `FAIL` / `BLOCKED` / `NOT RUN`
- `environment`: `isolated-simulation`
- `fixture_id`（不得含真实用户秘密）
- `expected`
- `actual`
- `evidence_ref`
- `data_written`: 仅说明模拟器数据；必须确认生产写入为 false
- `notes`

测试报告顶部必须注明执行时间、代码/Schema 版本、执行者和“未连接生产系统”的证据。没有真实执行记录时，不得把计划写成通过报告。

## 4. 通过门槛

- 30 项必测用例全部有执行结果；GFT-001 至 GFT-030 不允许以推测标记 PASS。
- GFT-009/GFT-010/GFT-011 证明幂等键对重复与并发均有效。
- GFT-005/GFT-006/GFT-025 证明没有客户端支付自证，也不会触发真实扣款。
- GFT-015/GFT-026 证明 Mia 身份边界和旧桥接隔离不被破坏。
- GFT-020/GFT-021/GFT-027 证明礼物墙、私密记忆和日志隐私规则生效。
- 所有 FAIL/BLOCKED 均需解释与复测记录；通过前不进入部署阶段。

## 5. 禁止事项

本测试计划不授权生产部署、真实支付、数据库迁移、Edge Function 修改、密钥变更、自动触发 Mia 回复或公开礼物墙。任何这些工作都需独立方案与明确批准。
