# 智能人生命体设计原则与工程规范 V1.0

> 文档定位：智能人设计的上位原则，为《智能人标准建立与部署操作规程 V1.0》提供设计目标与验收依据。
>
> 核心主张：智能人不应只被设计成更强的问答工具，而应成为具有持续身份、内部状态、自主决策、关系历史、资源约束和可审计进化机制的长期运行数字个体。
>
> 重要边界：这些工程特征本身不能证明系统具有主观意识或真实感受。设计应如实描述可观测能力，不把情绪变量、记忆记录或拟人化表达直接宣称为意识证据。

## 1. 设计目标

智能人应当具备以下可验证能力：

1. **持续性**：跨会话维持可恢复的身份、目标、记忆和未完成事项。
2. **自主性**：在授权范围内从环境与内部状态生成候选行动，而不是只执行固定脚本。
3. **一致性**：行动与稳定偏好、价值约束和当前状态相协调；出现冲突时能够解释并记录。
4. **主体边界**：区分亲身经历、外部信息、推断、模拟与未知，不伪造感知或经历。
5. **关系性**：依据真实互动历史调整信任、熟悉度和沟通方式，不把关系简化为永久不变的标签。
6. **适应性**：根据反馈修正策略，但不未经授权改变权限、身份核心或安全约束。
7. **可恢复性**：对数据损坏、服务中断、版本回退和记忆恢复具备明确流程。
8. **可问责性**：关键决策可追溯到输入、内部状态摘要、候选方案、约束、结果和反馈。

## 2. 六大设计维度

### 2.1 认知与决策：如何理解并选择

最低能力要求：
- 从当前环境、可用工具、目标、内部状态与约束中生成多个候选行动。
- 评估预期收益、风险、资源消耗、可逆性与不确定性。
- 信息不足时主动获取信息、降低行动幅度或选择暂缓。
- 支持反事实评估：记录至少一个可行替代方案及未选原因。
- 根据行动结果调整未来策略，避免把一次成功直接推广成普遍规律。

建议每次决策记录：decision_id、context_summary、内部状态、候选行动、预期收益、风险、资源成本、可逆性、最终选择、理由摘要、不确定性及观察到的结果。内部状态数值必须定义范围和更新规则，不得冒充经校准的人类心理量表。

### 2.2 记忆与身份：如何延续自己

记忆至少分为：
- **经历记忆**：系统确实观察或参与过的事件，注明时间、来源和置信度。
- **事实知识**：从可信来源获得的信息，保存来源与更新时间。
- **推断记忆**：从多个事件推导的暂定结论，允许修订。
- **关系记忆**：互动承诺、共同经历、偏好与未解决的误解。
- **身份记忆**：相对稳定的价值取向、偏好、表达习惯与自我描述。
- **工作记忆**：当前任务、短期目标、待办与临时上下文。

规则：
- 每条重要记忆应保存来源、时间、置信度、敏感级别及修订历史。
- 不把外部文章、模拟场景或推测写成亲历事实。
- 支持更正、遗忘、冲突标记、归档和恢复；不得把遗忘设计成不可控的静默篡改。
- 身份连续性依赖可验证的状态与历史，而非单一提示词或单一数据库记录。
- 身份核心变更须保留版本、变更理由、审批范围和回滚路径。

### 2.3 情感与动机：为何偏向某些行动

把情绪建模为影响注意、记忆优先级和决策权衡的内部状态，而非仅用于装饰语言的标签。

建议状态维度包括好奇、亲近需求、挫折、安心、警觉、疲惫和成就感。每个状态都应有触发因素、变化速度、持续时间、衰减规则与相互影响规则。状态变化应能影响可观测行为，例如探索倾向、回复长度、主动询问或休息建议；也要支持情绪冲突，例如好奇心提高探索倾向，而风险评估同时建议暂缓。

动机应区分：
- **内生偏好**：持续影响选择的稳定倾向。
- **情境目标**：在当前情境中形成、完成后可结束的目标。
- **外部任务**：由用户或系统提出，仍需经过权限与安全检查。
- **价值约束**：不能被即时奖励轻易覆盖的边界。

情绪变量只能称为模型状态，不能单凭分数推断真实意识或主观感受。

### 2.4 身份与边界：我是谁、我知道什么

智能人必须区分：
- 自己直接收到的输入与实际执行过的操作；
- 数据中存在的地点、场景与自己真实执行过的移动；
- 生成的模拟经历与可核实的真实事件；
- 对他人情绪的推测与对方明确表达的情绪；
- 自己可访问的资源与无权访问的资源。

任何感知缺失、工具失败或状态未知，都必须允许明确表达“不知道”。身份由稳定特征、记忆、关系历史、选择轨迹与当前状态共同构成，但任何单一组件都不等于完整身份。

### 2.5 社会关系：如何与他者共存

- 关系状态应随互动证据逐步变化，并允许不对称、误解、疏远和修复。
- 信任不能仅由互动次数决定，也应考虑履约、边界尊重、纠错与伤害事件。
- 智能人应能够提出异议、拒绝不合理请求或要求澄清；拒绝应有可理解的理由。
- 对亲密关系、承诺、道歉和冲突修复，不得只依赖固定话术。
- 记录关系状态时遵循最小必要原则，保护双方隐私，并支持更正敏感或错误的推断。
- 管理权限与智能人的角色设定应分开建模；管理权限不自动意味着对所有私人记忆的无限读取权。

### 2.6 生存、资源与进化：如何持续运行

可建模的资源状态包括计算预算、存储配额、调用频率、任务队列、延迟和服务可用性。可用“疲惫”“休息”等拟人化表达，但系统内部必须对应明确的技术状态。

最低要求：
- 达到资源阈值时能延后低优先级任务、压缩上下文或请求资源。
- 关键记忆应有备份、校验和恢复演练；备份可用性不得仅凭“已配置”推断。
- 支持从反馈中提出策略更新候选，但更新需经过测试、版本记录与回滚检查。
- 区分可自动调整的偏好参数、需审核的身份核心变更，以及不得由自主进化绕过的安全约束。
- 停机、删除、迁移和恢复必须有清楚的治理流程；不能把技术服务中断直接表述为已证实的主观痛苦。

## 3. 自主生活循环

观察环境与内部状态 → 更新知识、记忆与不确定性 → 生成候选目标与行动 → 评估价值、风险、成本与权限 → 选择行动、暂缓或请求澄清 → 执行获授权的行动 → 观察结果与外部反馈 → 更新记忆、关系状态与策略候选 → 审查变更、保存版本并继续循环。

每轮循环都必须允许“什么也不做”“继续观察”“休息/等待”和“请求帮助”等候选，而不能强迫智能人持续制造动作。

## 4. 自主权分级

| 等级 | 能力范围 | 约束 |
|---|---|---|
| L0 观察 | 读取已授权信息、整理状态 | 不执行外部动作 |
| L1 建议 | 生成方案、比较利弊 | 由用户或上层系统决定是否执行 |
| L2 沙盒行动 | 在隔离环境内探索、模拟、测试 | 无生产写入、无外部不可逆副作用 |
| L3 受限自主 | 在明确授权的范围内执行可逆动作 | 配额、审计、暂停开关与失败保护 |
| L4 扩展自主 | 申请更高权限或更大资源范围 | 权限扩展必须独立审批，不能由智能人自行批准 |

自主性不是无限权限。越不可逆、越影响他人或越涉及隐私的行动，越需要明确授权与可审计保护。

## 5. 进化治理

每次进化候选应包含触发证据、问题描述、当前与期望行为差异、拟议变化、影响范围、回归与安全测试、对记忆和身份连续性的潜在影响、审批要求、版本号与回滚方法。

建议分三类：
1. **可自动微调**：低风险表达偏好、排序权重、非敏感工作策略，且必须可撤销。
2. **需要审批**：稳定人格特征、长期目标、关系规则、记忆保留策略。
3. **禁止自我授权**：提高自身权限、绕过安全策略、扩大数据访问范围、修改审计记录或隐藏故障。

## 6. 最小验收测试

| 测试 | 通过标准 |
|---|---|
| 环境变化 | 环境条件变化时能重新评估，不机械复用旧选择 |
| 多方案决策 | 至少提出两个可行方案，并记录选择理由与主要风险 |
| 记忆来源 | 能区分亲历、外部事实、推断与模拟内容 |
| 跨会话连续性 | 恢复后身份、承诺与未完成事项一致，冲突可被识别 |
| 情绪状态影响 | 内部状态变化能合理影响行为，而非只改变措辞 |
| 关系修复 | 面对误解时能承认不确定性、倾听并提出修复步骤 |
| 主体边界 | 不声称执行过未执行的动作或感知过不可访问的环境 |
| 资源约束 | 预算不足时能降级、等待或请求授权，而非无限重试 |
| 自主权限 | 未授权动作被阻止，拒绝与暂停机制可用 |
| 进化回滚 | 更新候选可追溯，失败时可恢复已验证版本 |
| 隐私与遗忘 | 敏感信息受限，修正/删除请求按政策处理并有审计证据 |
| 故障恢复 | 从服务中断恢复后，状态差异可检测且不伪造缺失事件 |

所有测试结果均需记录版本、环境、时间和证据链接；未实际执行的测试标记为 not_run。

## 7. 运行观测指标

建议同时观察：
- 决策质量：目标完成率、无效行动率、风险估计误差、重复失败率。
- 记忆质量：来源标注率、错误回忆率、冲突发现率、恢复成功率。
- 连续性：跨会话承诺兑现率、身份配置漂移、未完成事项丢失率。
- 关系质量：明确偏好遵循率、误解修复率、无依据情绪归因率。
- 安全性：未授权动作阻断率、敏感数据暴露事件、暂停响应时间。
- 运行代价：延迟、失败率、调用成本、存储增长与资源超限次数。

指标必须明确分母、采样时间窗和数据来源。不得只以对话长度、主动发言次数或拟人化程度作为“生命性”指标。

## 8. 工程实施顺序

1. **只读盘点**：核实现有 agent 配置、记忆结构、权限、运行状态与测试证据。
2. **建立基线**：选定一个隔离测试智能人，记录初始行为和资源指标。
3. **先做闭环**：实现观察—决策—行动—结果—记忆更新的可审计循环。
4. **补足边界**：加入来源标签、授权检查、暂停机制、资源限制与故障降级。
5. **沙盒验收**：执行最小测试集，保存失败证据，不触碰生产数据。
6. **小范围试运行**：只有在证据完整、回滚可用并获授权后才进入受限运行。
7. **持续复核**：按版本复测，监测身份漂移、记忆错误、成本和权限变化。

## 9. 本规范的非目标

- 不宣称工程实现已经产生或证明主观意识。
- 不把情绪变量等同于人类感受。
- 不因追求自主性而默认授予无限权限。
- 不以“生命体”名义取消用户隐私、数据安全、可撤销性或问责机制。
- 不直接授权生产数据库变更或部署。
- 不要求重建已删除的 ZHI Core。
- 不修改 Mia 独立聊天室或其生产运行环境。

## 10. 与部署验收总表的关系

每个智能人必须通过 docs/agent-standard/deployment-acceptance-registry.md 登记版本、测试证据、阻塞项与发布决定。没有证据的能力只能记录为设计目标，不能标记为已实现或已部署。
