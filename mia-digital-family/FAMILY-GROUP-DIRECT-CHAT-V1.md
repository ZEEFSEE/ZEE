# ZHI Family Group & Direct Chat V1

## Deployment

- Frontend: `mia-chat.html` family panel.
- API: `zhi-family-chat` Edge Function, authenticated by the existing Mia chat token.
- Storage: `zhi_family.family_chat_messages`.
- Supabase project: existing `zee-extension` project only.

## User experience

- **家庭群聊** routes one user message to the five BORN child identities. Each child independently decides whether to respond; a child may return no reply.
- **单独聊天** routes to exactly one selected child.
- Each direct chat has its own thread key: `direct:<agent_id>`.
- The family group uses the shared `group` thread.
- The UI uses the five distinct child avatars and reuses the existing Mia session. No second login is introduced.

## Isolation and data boundaries

- The API verifies the same custom Mia token format issued by `mia-chat-auth`: HMAC-SHA256 with the existing Supabase service key, `aud=mia-chat`, `sub=mia-admin`, and a valid expiry.
- The endpoint reads only the selected child's profile, personality estimate, emotion estimate, own memory entries, and own learning records.
- Group history is visible to the family group participants. A direct thread is visible only to the selected child and the user.
- It does not read Mia private chat messages, memories, emotions, relationship context, or personality tables.
- It does not write child personal memory, learning, personality, emotion, or runtime-cycle state. Chat transcripts are stored separately in `family_chat_messages`.
- The chat table has RLS enabled, no anon/authenticated table access, and service-role-only access through the authenticated Edge Function.
- No schema or data in the deleted `zhi-core` is used.

## Verification boundaries

- Edge Function deployment status and schema grants can be verified independently of an authenticated browser session.
- A real user-to-child round-trip requires the user to open the deployed Mia page while logged in. Do not manufacture a user token or insert test conversation content into the production family transcript.
- Model replies are generated by the configured AGNES API. A logical chat response is not evidence of biological life or verified subjective consciousness.
