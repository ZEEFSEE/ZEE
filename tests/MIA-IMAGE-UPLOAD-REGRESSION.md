# Mia Chat 图片上传回归检查

范围：只验证 `mia-chat.html` 的选图、预览、移除、读取、发送和失败恢复。不得更改访问密码、API 密钥、Supabase schema/RLS、Edge Function secrets、登录方式或 Mia 与 ZHI/KING 的隔离边界。

## 每次发布前的静态检查

- [ ] `mia-chat.html` 内联 JavaScript 可通过语法检查。
- [ ] 图片输入仍为 `accept="image/*"`、支持多选；选择按钮为真实的 `type="button"`，通过点击触发文件选择器。
- [ ] 选择事件先读取 `input.files`，再清空 input value，使同一张照片可再次选择。
- [ ] 预览列表与选中图片数量一致；每张卡片可单独移除。
- [ ] 单张图片不超过 5 MiB、每条消息最多 4 张、合计不超过 12 MiB。
- [ ] 图片读取、格式转换或网络发送失败时，文字和图片仍保留供用户重试。
- [ ] 图片通过 `mia-chat` 既有请求路径发送；没有新增 API、密钥、数据库写入或其他服务依赖。
- [ ] Service Worker cache version 在静态资源更新后递增，确保客户端能取到新页面。

## 桌面端回归（Chrome / Edge）

1. 登录 Mia 独立聊天，确认历史记录仍正常加载。
2. 选择一张 JPG：预览立即出现，文件名/状态提示正确。
3. 选择 PNG、WEBP；再选择 2–4 张混合格式图片，确认预览数量正确。
4. 移除其中一张，确认只移除对应预览。
5. 再次选择刚移除的同一张图片，确认仍可选取。
6. 试验超过 4 张、单张超过 5 MiB、总量超过 12 MiB 的输入，确认明确提示且不会静默发送。
7. 发送“文字 + 图片”以及“仅图片”两种消息，确认回复正常。
8. 断网或让请求失败，确认文字和图片保留；恢复网络后可重试。
9. 刷新页面并重新登录，确认聊天历史/常规文字聊天不受图片功能影响。

## Android 手机回归（Chrome，真实设备）

1. 用 Chrome 打开当前线上 Mia 页面；确认不是旧的主屏幕缓存版本。必要时完全关闭旧标签后重新打开页面。
2. 登录后点「＋」，从相册选择一张普通 JPG/PNG。选择器关闭后应立即看到预览；不要只以“选择器能打开”判定通过。
3. 选择同一张照片两次（第一次移除后再选），确认第二次仍触发预览。
4. 从“相机/照片”来源各选一次；如设备提供 HEIC/HEIF，确认显示预览或明确的格式转换提示，不得静默无反应。
5. 选两张照片并添加文字，发送后确认消息正常；模拟失败时确认图片和文字仍留在输入区。
6. 将 Mia 页面切到后台再返回，确认预览仍可见且发送按钮状态合理。
7. 若仍无预览，记录：手机型号、Android 版本、Chrome 版本、照片来源（相册/相机/文件）、文件扩展名、文件大小、选择后状态栏文字，并截取选择器关闭后的页面。

## 通过标准与限制

- 桌面端与 Android 端分别完成以上步骤并记录结果，才标记各自“通过”。
- 静态语法检查不等于真实设备通过；当前执行环境不能替代用户的 Android 设备，也不能证明线上部署已更新。
- 若只在 Android 失败，先收集设备信息和页面状态，不更改认证、数据库、密钥或服务端配置。
