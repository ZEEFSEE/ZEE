# ZHI Digital Family — Isolated Prototype V1

This directory is an isolated, non-production prototype for the proposed five-child digital family.

## Scope

- Five distinct child identifiers: LUNA, ARIA, ELYA, KAEL, NOAH.
- In-memory-only communication simulation with explicit volatile-session cleanup.
- All-or-nothing birth-state simulation; this is not a durable distributed transaction.
- Birth-time memory baseline is empty.
- Read-only audit of the existing five-destination world manifest.
- Destination access remains blocked; no child access is granted.
- No connection to Mia's production chat, AGNES API, Supabase, AURORA, Federation, or production world permissions.

## World audit findings

The current manifest contains Forest Corner plus five destination scenes and declares bidirectional portal routes from Forest Corner. Its scope remains `principal: prototype-mia`, `other_agents_access: false`, `aurora_enabled: false`, and `federation_enabled: false`. The five scene-transition contracts report `contract_defined_runtime_validation_pending`; they are not proof of working runtime travel. The family adapter only audits these facts and never changes permissions.

## Important limitations

This prototype is a deterministic software test harness. It does **not** create autonomous minds, establish subjective consciousness, create production Agent accounts, provide persistent memory, prove real-time privacy across external logs/telemetry, or prove live 3D navigation. The sample messages used by tests are fixtures, not messages generated by running child agents.

The birth simulator's readiness flags are test inputs. A `cleanupVerified: true` test fixture is not a real storage cleanup attestation. The synchronous in-memory commit is not a durable database transaction and must not be used for production birth.

## Run locally

Requires Node.js 20 or later:

```sh
node --test mia-digital-family/tests/*.test.mjs
```

GitHub Actions runs the same tests on changes to this isolated branch.

## Promotion gates

Do not merge into the production branch or connect external services until:
1. persistent-storage and telemetry paths have been reviewed;
2. a durable atomic transaction/recovery design has been implemented and tested;
3. five-destination navigation has been independently validated;
4. per-agent access grants have been reviewed;
5. a separate integration plan has been explicitly approved.
